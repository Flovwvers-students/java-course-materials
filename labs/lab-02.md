## Задания

По указанию преподавателя сдаём только задания **2.1–2.4**. Пункт 2.5 из исходной методички не требуется.

### 2.1. BankAccount

Банковский счёт: имя вкладчика, строковый номер счёта, баланс. Создание и инициализация; отображение данных строкой; пополнение; снятие заданной суммы; полное и сокращённое строковые представления (в сокращённом скрыть баланс).

### 2.2. Bank

Банк хранит счета из 2.1: динамический массив либо ArrayList. Максимальное и текущее число клиентов хранить, если это требуется выбранной реализацией. Инициализация списка; добавление счёта; поиск по имени; закрытие по имени; вывод клиентов со счетами; общий баланс; корректное завершение работы с объектом.

### 2.3. Vector3D

Трёхмерный вектор с приватным массивом вещественных компонент. Конструктор; доступ к компоненте только на чтение; длина; угол; умножение на число; сложение; вычитание; скалярное и векторное произведения. **Неизменяемый объект (Immutable)**: операции возвращают новый вектор, исходный не меняется; не выдавать изменяемый внутренний массив. Переопределить toString, equals и hashCode. Формулировка про «изменение текущего вектора» в исходнике трактуется с учётом требования Immutable.

### 2.4. LinVector<T>

Обобщённый класс вектора с приватными/защищёнными компонентами. Нулевой вектор по умолчанию; различные конструкторы, включая копирование; чтение компоненты; сложение; вычитание; умножение на число; скалярное произведение; норма. Проверка размеров и обработка ошибок обязательны. Стратегия неизменяемого объекта. Числовые ограничения T и способ реализации арифметики объяснить в README.

## Что отправить

Один PR на всю лабораторную. Код и README находятся в `lab-01/` или `lab-02/` соответственно. В README лабораторной укажите выполненные задания и ссылки на исходники, точные команды сборки/запуска, проверочные примеры с ожидаемыми и фактическими результатами, известные проблемы и таблицу использования ИИ. Шаблон уже подготовлен в репозитории.

Не загружайте исполняемые файлы, .class, объектные файлы и каталоги сборки. Задания лабораторной №1 оформляйте отдельными программами; в №2 связанные классы переиспользуйте. Допустима эквивалентная понятная структура — уже работающий код не нужно переписывать только ради названий каталогов.

Если работу уже приняли ранее, всё равно оформите PR и напишите: **«Уже принято преподавателем — требуется только учёт в GitHub»**, добавив когда и как сдавали.

## Критерии проверки

Соответствие каждому условию, компиляция по указанным командам, корректность на обычных и граничных входах, предусмотренная условием обработка ошибок, полнота README и отчёта об ИИ. Искусственно создавать ошибку или получать Request changes не требуется: доработка нужна при реальных замечаниях.
