# Сдача лабораторных через GitHub

Вместо YOUR_REPOSITORY подставляйте имя своего именного репозитория, указанное преподавателем. Условия — в [каталоге лабораторных](../labs/README.md), собственный Issue сохраняется для приёмки.

> Не делайте самостоятельный Merge или push в main. Преподаватель принимает и сливает лабораторные. Один PR на лабораторную; исправления — в ту же ветку.

## Структура

Git не хранит пустые папки. Сейчас созданы только README и шаблон PR; каталоги исходников и проверок создавайте вместе со своими файлами.

```text
README.md
.github/pull_request_template.md
lab-01/
  README.md
  src/       — отдельные программы заданий 01–11
  tests/     — собственные проверочные данные или тесты
lab-02/
  README.md
  src/bank/        — BankAccount и Bank
  src/vectors/     — Vector3D и LinVector
  tests/           — проверки
```

В лабораторной №2 банк использует класс счёта из предыдущего задания. Не создавайте независимые копии связанных классов. Структура может быть эквивалентной, если понятны исходники и запуск. В README каждой лабораторной заполните отчёт о решении, примерах и использовании ИИ.

## Короткая памятка: от клонирования до сдачи

Нужны установленные Git и GitHub CLI (`gh`); полная настройка и университетский прокси описаны в общей методичке преподавателя. На университетском компьютере работайте в папке `github` на своём сохраняемом сетевом диске, а не во временном профиле на C:. Буква диска может отличаться. Команды ниже одинаковы в PowerShell, CMD и Linux/macOS, если не указано иное.

### 1. Авторизоваться и клонировать

Примите приглашение в репозиторий. Откройте терминал в своей сохраняемой папке `github` и выполните:

```sh
gh auth login --hostname github.com --git-protocol https --web
gh auth setup-git
git clone https://github.com/Flovwvers-students/YOUR_REPOSITORY.git
cd YOUR_REPOSITORY
```

Клонирование выполняется один раз. Если папка уже есть, откройте её. После сброса университетской сессии при необходимости повторите авторизацию и настройки из общей методички. Для коммитов задайте **свои** имя и email локально в репозитории:

```sh
git config user.name "Ваше имя и фамилия"
git config user.email "Ваш email GitHub или noreply-адрес из настроек GitHub"
```

### 2. Создать ветку лабораторной

Сначала убедитесь через `git status`, что нет несохранённых изменений. Для №1:

```sh
git switch main
git pull --ff-only origin main
git switch -c lab/01
```

Для №2 используйте `lab/02`. Для каждой лабораторной создавайте отдельную ветку от актуальной main. Если ветка уже создана, переключитесь на неё: `git switch lab/01`.

### 3. Сделать коммит

Добавьте код, заполните `lab-01/README.md`, проверьте сборку и запуск. Для №2 замените путь на `lab-02`.

```sh
git status
git add lab-01
git diff --cached
git commit -m "Complete laboratory 1"
```

Перед коммитом проверьте список: не добавляйте пароли, токены, исполняемые файлы и результаты сборки.

### 4. Отправить ветку

```sh
git push -u origin lab/01
```

### 5. Создать Pull Request

```sh
gh pr create --base main --head lab/01 --web
```

В открывшейся форме заполните шаблон и студенческие чекбоксы. Укажите `Closes #1` для №1 или `Closes #2` для №2. Создайте PR и отправьте преподавателю ссылку. Чекбоксы в Issue не трогайте. **Merge не нажимайте.**

### 6. Исправить замечания и отправить на повторную проверку

Новый PR не создавайте. В той же папке и ветке:

```sh
git switch lab/01
```

Внесите исправления и обновите README лабораторной, затем:

```sh
git add lab-01
git diff --cached
git commit -m "Address review comments for laboratory 1"
git push
```

Открытый PR обновится автоматически. Ответьте в нём на замечания и запросите повторную проверку кнопкой повторного запроса review, если она доступна, либо комментарием преподавателю. Если замечаний нет, этот шаг не нужен. Если PR уже закрыт или слит, сначала сообщите преподавателю — не удаляйте работу и не делайте force-push.

**Слияние выполняет только преподаватель.**
