Требования к оформлению кода (Java)
Это соглашения, которым должен следовать любой код, который вы сдаёте. Стиль, компиляция и логика проверяются за один проход. Для лабораторной №1 действует послабление по стилю.
1. Порядок членов класса
Внутри класса всё располагается строго в этом порядке:
private static final константы
Остальные static поля
Поля экземпляра (всегда private)
Конструкторы
Методы: сначала геттеры (сразу после конструкторов), затем остальные методы, сгруппированные по смыслу — метод лежит рядом с тем методом, который его вызывает
Вложенные классы и enum'ы — в самом конце
Пример правильного порядка:
class Order {
    private static final String TOTAL_FORMAT = "Итог: %.2f";
    private static int totalOrders = 0;
 
    private OrderLine[] lines;
 
    public Order(OrderLine[] lines) {
        this.lines = lines;
        totalOrders++;
    }

     public static int getTotalOrders() {
        return totalOrders;
    }

    public double getTotal() {
        return calculateTotal();
    }

    public void printTotal() {
        System.out.println(String.format(TOTAL_FORMAT, getTotal()));
    }
 
    private double calculateTotal() {
        double total = 0.0;
 
        for (OrderLine line : lines) {
            total += line.getPrice();
        }
 
        return total;
    }
}
2. Именование

Стиль
Пример
Классы, интерфейсы, enum'ы
UpperCamelCase
BankAccount, OrderLine
Методы и переменные
lowerCamelCase

UPPER_SNAKE_CASE
DEFAULT_SALARY, RATE_PER_KG
Требования к именам:
Имена методов — глаголы или глаголы с дополнением: calculateCost, borrowBook.
Имена классов — существительные: Parcel, Warehouse.
Имена констант раскрывают смысл значения: RATE_PER_KG = 50.0, а не RATE = 50.0 и не K = 50.0.
Сокращения запрещены. qty, prc, tmp — не принимается. quantity, price — принимается.
Однобуквенные имена запрещены везде, включая параметры catch: e — не принимается, exception — принимается. Исключения — переменные цикла i, j в простом for по индексу и x, y, z для координат.
3. Именованные числа и переиспользуемые строки
Уточнение преподавателя 31.10.2026 для Java: одноразовые понятные сообщения и форматы вывода разрешены прямо в месте использования (например, String.format внутри getFullInfo). Не требовать отдельную константу только из-за наличия строкового литерала. Повторяющиеся строки и общие настройки формата выносить в именованные константы. Правила числовых литералов и тестовых данных сохраняются.
Числа вне перечисленных ниже исключений должны жить в «коробке с названием»: в именованной константе или в именованной переменной.
Допустимо для одноразового понятного формата (уточнение 31.10.2026):
System.out.println(String.format("Итог заказа: %.2f", total));
Не следует писать без именования числового порога:
if (discount > 0.05) { ... }
Хорошо:
private static final String ORDER_TOTAL_FORMAT = "Итог заказа: %.2f";
private static final double MINIMUM_DISCOUNT = 0.05;
 
System.out.println(String.format(ORDER_TOTAL_FORMAT, total));
 
if (discount > MINIMUM_DISCOUNT) { ... }
Что считается коробкой:
повторяющиеся строки и общие настройки формата — в static final константы; одноразовые понятные сообщения и форматы могут оставаться в месте использования;
тестовые данные в main — в локальные переменные с говорящими именами: double lunchPrice = 450.0;, а не new OrderLine("Обед", 450.0, 1, 0.10); из ниоткуда.
Допустимые исключения (литерал допустим без коробки):
0 и 1 как индексы, счётчики циклов и единицы в простых формулах;
начальное значение локального аккумулятора (double total = 0.0;);
true, false, null;
литералы внутри одного заранее объявленного набора данных (List.of("Обед", "Ужин"), инициализатор массива) — коробкой считается сама переменная/константа, в которую кладётся набор, а не каждый элемент по отдельности.
Пример на последнее исключение:
// Хорошо — набор целиком является "коробкой"
private static final List<String> MEAL_NAMES = List.of("Обед", "Ужин", "Завтрак");
 
// Плохо — отдельные элементы всё равно магические, если набор не назван
process(List.of("Обед", "Ужин", "Завтрак"));
Для чисел действуют перечисленные исключения; для строк — разрешение одноразовых понятных сообщений и форматов. Не требовать константу вопреки этому разрешению.
4. Поля и инкапсуляция
Все поля экземпляра — private. Без исключений.
Публичными могут быть только public static final константы.
Приватным полям префикс _ НЕ ставится. Это C#-стиль, в Java его нет: private double balance;, а не private double _balance;.
Если параметр конструктора или метода называется так же, как поле, обращение к полю — только через this: this.balance = balance;.

5. Оформление
Отступ — 4 пробела, без табов.
Открывающая фигурная скобка — на той же строке (стиль K&R):
public double calculateCost() {
    return baseCost + weight * RATE_PER_KG;
}
Пробелы вокруг операторов: бинарные операторы и присваивание пишутся с пробелами по обе стороны — a + b, price * (1 - discount), total += line.getPrice(), if (available && discount > MINIMUM). Исключение — унарные операторы: count++, -armor.
if, for, while, switch, try обрамляются пустыми строками сверху и снизу — если там есть другой код. Если конструкция первая после открывающей скобки блока или последняя перед закрывающей, пустая строка не нужна:
public double getTotal() {
    double total = 0.0;
 
    for (OrderLine line : lines) {
        total += line.getPrice();
    }
 
    return total;
}
Не более одной пустой строки подряд. Если хочется отделить крупный смысловой блок — используйте метод или класс, а не вертикальные дыры.
Один класс — в одном файле, имя файла совпадает с именем класса.
Переопределение методов помечается @Override.
Строка кода — не длиннее 120 символов. Длинные вызовы и условия переносятся по операторам, новая строка начинается с оператора:
if (discount > MINIMUM_DISCOUNT
        && customer.isRegular()) {
    applyDiscount();
}
6. Импорты
Wildcard-импорты (import java.util.*;) запрещены — каждый класс импортируется отдельной строкой.
Порядок: сначала java.*/javax.*, затем всё остальное, каждая группа отсортирована по алфавиту, между группами — одна пустая строка.
Импорты отделены от основного кода пустой строкой.
Плохо:
import java.util.*;
import com.shop.pricing.DiscountPolicy;
import com.shop.order.OrderLine;
import java.util.List;
class Order {...
Хорошо:

import java.util.List;
 
import com.shop.order.OrderLine;
import com.shop.pricing.DiscountPolicy;

7. Сравнение и равенство
Объекты (String, обёртки Integer/Double и т.п., любые классы) сравниваются через .equals(), а не ==. == — только для примитивов.
Если класс переопределяет equals(), он обязан переопределить и hashCode() — пара переопределяется вместе, никогда по отдельности.
Плохо:
if (customerName == CUSTOMER_IVANOV) { ... }
Хорошо:
if (customerName.equals(CUSTOMER_IVANOV)) { ... }
Пример пары equals/hashCode:
@Override
public boolean equals(Object other) {
    if (this == other) {
        return true;
    }
 
    if (other instanceof OrderLine == false) {
        return false;
    }
 
    OrderLine otherLine = (OrderLine) other;
 
    return name.equals(otherLine.name) && price == otherLine.price;
}
 
@Override
public int hashCode() {
    return Objects.hash(name, price);
}
8. Исключения
Пустой catch { } запрещён — в блоке обязательно должна быть обработка (логирование, проброс дальше, осмысленное сообщение).
catch (Exception e) без более узкого типа запрещён, если только явно не требуется поймать несколько разнородных исключений сразу.
Параметр catch называется exception, а не e — однобуквенные имена запрещены (см. п.2).
Плохо:
try {
    order.save();
} catch (Exception e) {
}
Хорошо:
try {
    order.save();
} catch (IOException exception) {
    System.out.println(SAVE_ERROR_MESSAGE);
}
9. Что проверяется при сдаче
Код компилируется и делает то, что написано в легенде задачи.
Числа оформлены с учётом исключений; повторяющиеся строки и общие настройки формата названы. Одноразовые понятные сообщения и форматы допускаются без отдельной константы.
Порядок членов класса и именование — по этому документу.
Каждое поле private, каждый переопределённый метод помечен @Override.
Нет wildcard-импортов, == для объектов, пустых catch.
Пустые строки и пробелы как описано в документе.
Нарушения пунктов 2–5 учитываются вместе с результатами проверки логики; для лабораторной №1 действуют послабления.
